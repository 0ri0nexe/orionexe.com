Antisèche Cisco IOS

Uniquement les commandes tapées en TP, dans l'ordre d'une séance : se connecter, configurer, vérifier.

1. Se connecter et se repérer

$ sudo screen /dev/ttyUSB0 9600    # câble console, puis Entrée
# pour sortir : Ctrl-A, puis k, puis y

Au premier démarrage, répondre n à initial configuration dialog. Sous Windows, même chose avec PuTTY (Serial, 9600).

? liste ce qu'on peut taper, Tab complète, et les abréviations marchent (conf t, sh run, int f0/1). Préfixer par no annule une commande. Sur Catalyst 9200, f0/X s'écrit g1/0/X.

2. Configuration de base TP1 TP2

Switch> enable
Switch# delete vlan.dat                 ! repartir sans VLANs (TP5)
Switch# clock set 15:08:00 Oct 26 2026
Switch# configure terminal
Switch(config)# hostname S1
S1(config)# no ip domain-lookup          ! une faute de frappe ne bloque plus 30 s
S1(config)# enable secret class         ! mot de passe du mode #
S1(config)# line console 0
S1(config-line)# password cisco
S1(config-line)# login                  ! sans login, le mot de passe n'est pas demandé
S1(config-line)# exit
S1(config)# banner motd # Acces reserve #

3. Adresse IP du switch (SVI) TP2 TP5

S1(config)# interface vlan 99             ! vlan 1 en TP2
S1(config-if)# ip address 192.168.1.11 255.255.255.0
S1(config-if)# no shutdown
Pour comprendre

Les ports d'un switch n'ont pas d'IP : il transmet des trames sans les lire au niveau IP. Pour pouvoir le pinger, on lui donne une IP sur une interface virtuelle, la SVI, rattachée à un VLAN. Elle n'est up que si au moins un port actif de ce VLAN existe. Dans le TP5, vlan 99 reste down tant qu'aucun port n'y est affecté.

4. VLANs et trunks TP5 TP6

! créer
S1(config)# vlan 10
S1(config-vlan)# name Operations
S1(config-vlan)# exit
! port vers un PC : un seul VLAN
S1(config)# interface f0/6
S1(config-if)# switchport mode access
S1(config-if)# switchport access vlan 10
S1(config-if)# no shutdown
! lien vers un autre switch : tous les VLANs
S1(config)# interface f0/1
S1(config-if)# switchport mode trunk
S1(config-if)# switchport trunk native vlan 1000   ! même valeur des deux côtés
Pour comprendre : access ou trunk

Un port access appartient à un seul VLAN et ne marque pas les trames : le PC ne sait même pas qu'il est dans un VLAN. Un port trunk transporte plusieurs VLANs sur un câble. Il ajoute à chaque trame une étiquette 802.1Q avec le numéro de VLAN, sauf pour le VLAN natif, envoyé sans étiquette. Si les deux bouts n'ont pas le même VLAN natif, ces trames atterrissent dans le mauvais VLAN.

Dans le TP5, on teste aussi switchport mode dynamic desirable : le trunk est alors négocié par DTP au lieu d'être forcé. Il se forme si l'autre côté est en trunk, desirable ou auto. auto + auto ne donne pas de trunk, car aucun des deux ne propose.

5. Spanning Tree TP6

S1(config)# spanning-tree mode pvst
S1(config)# spanning-tree vlan 1,10,30 root primary      ! S1 racine de ces VLANs
S2(config)# spanning-tree vlan 1,10,30 root secondary    ! S2 en secours
! sur les ports vers les PC uniquement
S1(config)# interface f0/11
S1(config-if)# spanning-tree portfast
S1(config-if)# spanning-tree bpduguard enable
Pour comprendre

root primary baisse la priorité du switch pour qu'il gagne l'élection du pont racine dans ces VLANs. Avec PVST+, il y a un arbre par VLAN : S1 racine de certains VLANs et S3 des autres, les trois liens servent au lieu d'en laisser un inutilisé. PortFast fait passer un port vers PC en forwarding tout de suite, au lieu d'attendre 30 s. BPDU Guard coupe ce port si un switch y est branché par erreur.

Règles de la salle B107

Ne jamais sauvegarder (write ou copy running-config startup-config) : la config reste en RAM et disparaît au redémarrage, c'est voulu. En fin de TP : delete vlan.dat, puis remettre câbles et équipements en place.
