Chapitre 02

Configuration de base d'un commutateur

Se connecter à un commutateur Cisco, circuler dans l'IOS, le configurer (nom, mots de passe, adresse IP) et sauvegarder.

L'essentiel en 30 secondes
  • On configure un commutateur en ligne de commande (CLI) : d'abord par le port console, plus tard à distance par SSH.
  • Modes IOS : > utilisateur, # privilégié (enable), (config)# configuration (configure terminal). exit remonte d'un niveau, end revient en #.
  • Configuration de base : hostname, enable secret, mot de passe + login sur line console 0 et line vty 0 15, banner motd.
  • running-config (RAM) = config active, perdue au redémarrage ; startup-config (NVRAM) = config enregistrée. On sauvegarde avec copy running-config startup-config.
  • Un commutateur reçoit son adresse IP de gestion sur une SVI (interface vlan 1), à activer par no shutdown.

Accéder à l'IOS et naviguer

Le système Cisco, l'IOS, s'utilise en ligne de commande depuis un émulateur de terminal (PuTTY). Deux accès :

  • Console : câble bleu sur le port CONSOLE, en série à 9600 bauds. Fonctionne sans adresse IP : obligatoire pour la première configuration.
  • SSH (TCP 22, chiffré) : accès à distance, possible seulement une fois le commutateur doté d'une adresse IP. Telnet (TCP 23) fait pareil en clair : à éviter.

Les modes de commande

L'IOS range les commandes dans des modes hiérarchiques. L'invite indique toujours où l'on se trouve :

ModeInviteÀ quoi il sert
UtilisateurSwitch>Consultation limitée, aucune modification.
PrivilégiéSwitch#Tout consulter, sauvegarder, redémarrer.
Configuration globaleSwitch(config)#Modifier les réglages de tout l'appareil.
Sous-modes(config-line)#, (config-if)#Configurer une ligne d'accès ou une interface.
Pour comprendre

Voyez les modes comme les étages d'un bâtiment sécurisé. Au rez-de-chaussée (>), on regarde par les vitres. Avec un badge (enable), on entre dans les bureaux (#) où l'on voit tout. Seule la salle des machines ((config)#) permet de toucher aux réglages, et chaque armoire (ligne, interface) a sa porte. Une commande refusée ? Vérifiez d'abord l'étage, c'est-à-dire l'invite.

Switch> enable
Switch# configure terminal
Switch(config)# interface vlan 1
Switch(config-if)# exit        ! retour en config globale
Switch(config)# line console 0
Switch(config-line)# end      ! retour direct en mode privilégié
Switch#
Piège classique

exit depuis (config-if)# ramène en (config)#, pas en #. Pour un show, utilisez end, ou restez en config avec le préfixe do (do show ip interface brief).

Structure d'une commande et aide

Une commande = une commande + des mots-clés imposés + des arguments choisis par vous (dans ping 192.168.1.2, l'adresse est un argument). Pour s'aider :

  • ? liste ce qu'on peut taper à cet endroit (clock set ? donne le paramètre attendu).
  • Tab complète un mot, et les abréviations sont acceptées tant qu'elles sont uniques : conf t, sh ip int br.
  • ↑ rappelle les commandes précédentes.
Switch# clock set ?
  hh:mm:ss  Current Time
Switch# clok
       ^
% Invalid input detected at '^' marker.   ! le ^ montre l'erreur
Switch# clock set 15:08:00
% Incomplete command.                       ! il manque la date

En labo, no ip domain-lookup évite qu'une faute de frappe bloque le terminal plusieurs secondes (l'IOS la prend pour un nom de machine).

Configuration de base

Sur tout équipement neuf : un nom unique, un mot de passe sur chaque porte d'entrée (console, accès distants, mode privilégié) et une bannière d'avertissement légal.

Switch(config)# hostname S1
S1(config)# enable secret class          ! protège le passage en mode #
S1(config)# line console 0               ! accès par le câble console
S1(config-line)# password cisco
S1(config-line)# login                   ! demande le mot de passe
S1(config-line)# line vty 0 15           ! accès distants (SSH/Telnet)
S1(config-line)# password cisco
S1(config-line)# login
S1(config-line)# exit
S1(config)# service password-encryption  ! masque les mots de passe affichés
S1(config)# banner motd # Acces autorise uniquement ! #

Les lignes VTY reçoivent les connexions distantes (16 sur un commutateur, de 0 à 15). Dans la bannière, # est un délimiteur qui encadre le message.

enable secret stocke le mot de passe sous forme hachée (irrécupérable) ; service password-encryption masque seulement les autres, avec un chiffrement faible.

Piège classique

Sans login, le mot de passe de la ligne est enregistré mais jamais demandé. password définit le mot de passe, login active la vérification : il faut les deux.

Enregistrer la configuration

Le commutateur garde deux versions de sa configuration :

  • running-config, en RAM : la configuration active. Chaque commande tapée s'y applique immédiatement, mais tout est perdu à l'extinction.
  • startup-config, en NVRAM : la configuration enregistrée, chargée au démarrage. Elle survit aux coupures de courant.
Pour comprendre

C'est un traitement de texte : la running-config est le document ouvert à l'écran, la startup-config le fichier enregistré sur le disque. Si le courant saute avant « Enregistrer », vous retrouvez la dernière version enregistrée. Et pour annuler des essais ratés non sauvegardés, il suffit de redémarrer (reload).

S1# copy running-config startup-config
Destination filename [startup-config]?   ! Entrée pour confirmer
[OK]

Affichage : show running-config / show startup-config. Repartir de zéro : erase startup-config puis reload.

Adressage IP et SVI

Pour communiquer en IP, chaque hôte (PC, serveur) a besoin de trois paramètres :

  • une adresse IPv4 : 4 nombres de 0 à 255, par exemple 192.168.1.10 ;
  • un masque de sous-réseau, par exemple 255.255.255.0 (noté /24), qui sépare la partie réseau de la partie hôte ;
  • une passerelle par défaut : l'adresse du routeur, utilisée pour joindre les autres réseaux.

On les saisit à la main (adressage statique, comme en TP) ou on les reçoit automatiquement d'un serveur DHCP (le cas par défaut à la maison).

Pour comprendre

Une adresse IP fonctionne comme une adresse postale : le masque dit où s'arrête le nom de la rue (le réseau) et où commence le numéro (l'hôte). Avec 192.168.1.10 et 255.255.255.0, la rue est 192.168.1 et le numéro .10. Deux machines de la même rue se parlent directement : 192.168.1.10 et 192.168.1.11, oui. Pour 192.168.2.11, autre rue, il faut passer par la passerelle, le « bureau de poste » du quartier.

Pourquoi un commutateur a besoin d'une IP

Pour transmettre des trames, un commutateur n'a besoin d'aucune adresse IP. Mais pour l'administrer à distance (SSH) ou le pinger, il en faut une. Elle se met non pas sur un port physique mais sur une SVI (Switch Virtual Interface), interface virtuelle interne : interface vlan 1 par défaut.

Pour comprendre

Un commutateur est comme le standard téléphonique d'un immeuble : il relie les appartements sans avoir de numéro. Pour joindre le gardien, il faut lui donner sa propre ligne. La SVI est cette ligne : elle n'occupe aucun port, mais elle est joignable depuis tous les ports du VLAN 1.

S1(config)# interface vlan 1
S1(config-if)# ip address 192.168.1.1 255.255.255.0
S1(config-if)# no shutdown                    ! désactivée par défaut
S1(config-if)# exit
S1(config)# ip default-gateway 192.168.1.254  ! pour être joint depuis un autre réseau

La SVI ne passe up qu'après no shutdown et si au moins un port actif appartient au VLAN 1 (un PC branché par exemple). On vérifie avec show ip interface brief :

S1# show ip interface brief
Interface        IP-Address      OK? Method Status   Protocol
Vlan1            192.168.1.1     YES manual up       up
FastEthernet0/2  unassigned      YES unset  down     down

Travaux pratiques

TP1 · Naviguer dans l'IOS via la console Catalyst 2960 · PuTTY

Objectif : se connecter en console, passer d'un mode à l'autre, lire la version de l'IOS et régler l'horloge.

  1. Brancher le câble console, ouvrir PuTTY en Serial (port COM ou /dev/ttyUSB0), 9600 bauds.
  2. Répondre no à « initial configuration dialog ».
  3. show version : version de l'IOS et nom de l'image.
  4. enable, puis clock set 15:08:00 Oct 26 2012 (aidez-vous de ?) et show clock.
Pourquoi faut-il passer en mode privilégié pour clock set ?

Le mode > ne permet aucune modification : il faut enable.

Comment empêcher un accès non autorisé par le port console ?

Mot de passe + login sur line console 0, enable secret, et baie fermée à clé.

TP2 · Paramètres de base du commutateur et des PC 2 × Catalyst 2960 · 2 PC

Objectif : relier 2 commutateurs et 2 PC sur le réseau 192.168.1.0/24, appliquer la configuration de base et vérifier par ping. Ne pas sauvegarder.

  1. Câbler : S1 F0/1 ↔ S2 F0/1, PC-A sur S1 F0/6, PC-B sur S2 F0/18.
  2. Adresser les PC en statique : PC-A 192.168.1.10/24, PC-B 192.168.1.11/24.
  3. Sur S1 : hostname, no ip domain-lookup, enable secret, mot de passe console + login, banner motd.
  4. SVI : interface vlan 1, ip address 192.168.1.1 255.255.255.0, no shutdown. Idem sur S2 avec .2.
  5. Vérifier : show running-config, show ip interface brief, puis ping entre tous les équipements.
Pourquoi certains ports sont « up » et d'autres « down » ?

Un port n'est up/up que s'il est relié à un équipement allumé ; sans câble, il reste down/down.

Qu'est-ce qui pourrait empêcher un ping entre les PC ?

Câble mal branché, adresse ou masque erroné, ou pare-feu du PC (fréquent sous Windows). Vers le commutateur : SVI restée en shutdown.

Testez-vous

1. Vous êtes en S1(config-if)#. Quelle commande vous ramène directement en S1# ?

end (ou Ctrl+Z). exit ne ramènerait qu'en S1(config)#.

2. Un mot de passe est configuré sur line console 0 mais n'est jamais demandé. Pourquoi ?

Il manque la commande login, qui active la vérification du mot de passe.

3. Le commutateur redémarre et toute la configuration de la journée a disparu. Que s'est-il passé ?

Les changements étaient dans la running-config (RAM) et n'ont pas été copiés dans la startup-config (NVRAM) avec copy running-config startup-config.

4. Sur quelle interface met-on l'adresse IP de gestion d'un commutateur, et pourquoi ne répond-elle pas au ping juste après ?

Sur la SVI (interface vlan 1). Elle est désactivée par défaut : il faut no shutdown, et au moins un port actif dans le VLAN 1.

5. PC-A (192.168.1.10/24) peut-il joindre 192.168.2.5 sans passerelle ?

Non. Avec le masque /24, la partie réseau de PC-A est 192.168.1 ; 192.168.2.5 est sur un autre réseau, il faut passer par la passerelle par défaut.

6. Pourquoi préférer SSH à Telnet ?

Telnet (TCP 23) transmet identifiants et commandes en clair. SSH (TCP 22) chiffre toute la session.
