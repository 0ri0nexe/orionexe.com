Chapitre 00

Environnement de travail et bootcamp

Les outils à maîtriser avant de parler de protocoles : le poste de la salle B107, la commande ip, la console des équipements Cisco, VirtualBox et Wireshark.

L'essentiel en 30 secondes
  • Évaluation par un QCM final. En TP, on ne sauvegarde jamais la configuration des équipements.
  • Toute modification réseau se fait dans une VM, jamais sur l'OS hôte.
  • ip a montre les adresses ; sudo ip address add 10.0.1.10/24 dev … en ajoute une, masque compris.
  • Console : sudo screen /dev/ttyUSB0 9600, sortie par Ctrl-A k y.
  • Une VM en NAT ne voit pas la maquette : il faut l'accès par pont sur net1.
  • Wireshark : capturer sur la bonne interface, puis filtrer à l'affichage (icmp).

Le cours et la salle B107

Le cours suit trois temps : les bases (réseaux, commutateur Cisco, modèles OSI et TCP/IP), la couche 2 (Ethernet, VLAN, Spanning Tree), puis la couche 3 et au-delà (IPv4, transport, routage, routage inter-VLAN). Supports et sujets de TP sont sur Moodle.

Une règle de salle : ne pas sauvegarder la configuration (ni copy running-config startup-config, ni write). Un équipement Cisco travaille sur la running-config (en mémoire vive) et recharge la startup-config au démarrage : sans sauvegarde, un redémarrage le rend propre au binôme suivant.

Le poste : hôte, VM, net0 et net1

Chaque PC tourne sous Linux (l'OS hôte) et lance des machines virtuelles avec VirtualBox. L'hôte sert seulement à ce qui ne change aucun réglage ; dès qu'on touche une adresse IP, on travaille dans la VM Ubuntu Generic (user / user), dont les changements disparaissent à l'arrêt.

Le PC a deux cartes réseau, ramenées sur la prise murale : net0 se branche sur la prise DISI (Internet), net1 sur la maquette (switch ou routeur). La prise marquée TP ne s'utilise pas. Un câble USB-série relie le PC au port console.

Les LED des ports sont le premier test : éteinte, le problème est physique (câble, mauvais port, port désactivé), inutile de chercher dans la configuration.

Lire et poser une adresse avec ip

La commande ip suit la forme ip OBJET ACTION : ip a (adresses), ip r (routes), ip link (état des interfaces). Le réflexe de diagnostic est ip -br a, une ligne par interface :

$ ip -br a
lo        UNKNOWN  127.0.0.1/8
enp0s3    UP       10.0.2.15/24
enp0s8    DOWN

Poser une adresse se fait en deux temps : activer l'interface, puis ajouter l'adresse avec son masque. Le réglage est temporaire (perdu au redémarrage).

# empêcher NetworkManager d'écraser l'adresse
$ sudo nmcli dev set enp0s8 managed no
$ sudo ip link set enp0s8 up
$ sudo ip address add 10.0.1.10/24 dev enp0s8
# en cas d'erreur : retirer l'adresse
$ sudo ip address del 10.0.1.10/24 dev enp0s8

ip address add ajoute sans remplacer : vérifiez avec ip a qu'il ne reste pas une ancienne adresse.

Pour comprendre : pourquoi le masque est indispensable

Le masque dit à la machine quelles adresses sont « sur son câble ». Avec 10.0.1.10/24, toutes les adresses de 10.0.1.0 à 10.0.1.255 sont des voisines, joignables directement. Si on oublie le /24, Linux pose un /32 : un réseau qui ne contient qu'une adresse, la sienne. C'est comme un annuaire où l'on ne serait inscrit que soi-même : le routeur 10.0.1.254, pourtant branché sur le même switch, devient injoignable et le ping échoue.

Accès console aux équipements

Le port console est une liaison série directe vers l'équipement, qui fonctionne sans aucune adresse IP. C'est le seul accès à un switch neuf. Les paramètres Cisco par défaut sont 9600 bauds, 8N1, sans contrôle de flux.

Côté Linux, l'adaptateur USB-série apparaît comme un fichier, en général /dev/ttyUSB0 (/dev/serial_port sur un 9200L). On l'ouvre avec screen, et sudo est nécessaire car ce fichier n'est accessible qu'à root et au groupe dialout :

$ ls /dev/ttyUSB*
$ sudo screen /dev/ttyUSB0 9600
# écran noir : appuyer sur Entrée
Switch> enable
Switch#

Sous Windows, PuTTY fait la même chose (mode Serial, vitesse 9600).

Touches dans screenEffet
Ctrl-A k yQuitter pour de bon : la session est tuée et le port libéré.
Ctrl-A dDétacher : la session continue en arrière-plan et garde le port.
Piège classique : la session fantôme

Fermer la fenêtre du terminal ou détacher la session ne libère pas le port série : le binôme suivant obtient Resource temporarily unavailable. Pour réparer : sudo screen -ls pour trouver la session, puis sudo screen -X -S <id> quit. Pour l'éviter : toujours sortir par Ctrl-A k y.

VirtualBox et Wireshark

VirtualBox fait tourner la VM sur le PC hôte. L'instantané Etat_initial des VM de la salle permet de revenir en arrière : ne le supprimez pas.

Choisir le mode réseau

Le réglage se trouve dans Configuration → Réseau → Adapter → Attached to. Deux modes comptent en TP :

  • NAT : la VM accède à Internet à travers l'hôte, avec une adresse privée (10.0.2.15) inventée par VirtualBox. Personne ne peut la joindre de l'extérieur.
  • Accès par pont (Bridged Adapter) sur net1 : la VM est posée directement sur le câble de la maquette, comme une machine physique de plus. C'est le mode des TP.

Montage recommandé : deux cartes, une en NAT pour Internet, une en pont sur net1 pour la maquette.

Pour comprendre : pourquoi une VM en NAT ne joint pas la maquette

En NAT, VirtualBox place la VM derrière une petite « box » privée, comme votre PC derrière la box Internet de la maison : elle peut sortir vers Internet, mais elle n'est pas sur le réseau de la maquette, et le switch ne voit jamais son adresse MAC. Un ping vers le switch part donc vers Internet par net0 et n'arrive nulle part. En pont, les trames de la VM sortent telles quelles sur net1 : le switch la voit comme n'importe quel PC branché sur son port.

Piège classique

Le mauvais mode réseau est la première cause de blocage en VM, et aucun message d'erreur ne le signale : le ping échoue, c'est tout.

Capturer avec Wireshark

Wireshark enregistre les trames qui passent par une interface et les décode couche par couche. Trois gestes suffisent :

  1. Choisir l'interface : celle qui va vers la maquette (la carte en pont), sinon on ne verra jamais le trafic du TP.
  2. Capturer court : démarrer, faire l'action (un ping par exemple), arrêter.
  3. Filtrer à l'affichage dans la barre du haut : icmp pour ne voir que les pings, ip.addr == 10.0.1.254 pour un hôte précis. Barre verte : filtre valide ; rouge : erreur de syntaxe.

Cliquer un paquet affiche ses couches : Ethernet (MAC), IP, puis ICMP, TCP ou UDP.

Pour comprendre : filtre de capture ou filtre d'affichage

Le filtre de capture (syntaxe host 10.0.1.10, réglé avant de démarrer) est un tamis posé avant le seau : ce qui ne passe pas est perdu. Le filtre d'affichage (syntaxe ip.addr == 10.0.1.10, dans la barre du haut) est une paire de lunettes : tout est dans le seau, vous choisissez seulement ce que vous regardez. En TP, capturez tout et filtrez à l'affichage.

Travaux pratiques

TP · Dix minutes dans le terminal VM Linux

Objectif : se déplacer, créer et supprimer des fichiers, enregistrer la configuration réseau dans un fichier.

$ mkdir -p ~/tp0 && cd ~/tp0 && pwd
$ ip a > reseau.txt          # > crée ou écrase
$ ip r >> reseau.txt         # >> ajoute à la fin
$ ls ~/tp0 && rm -r ~/tp0    # on regarde, puis on supprime
Pourquoi >> et non > pour la deuxième ligne ?

> écraserait le fichier : on perdrait la sortie de ip a. >> ajoute à la suite.

TP · Entrer dans le switch par la console salle B107

Objectif : ouvrir la console, passer en mode privilégié et relever la version d'IOS et le numéro de série.

  1. Trouver le port : ls /dev/ttyUSB*.
  2. Ouvrir la session : sudo screen /dev/ttyUSB0 9600, puis Entrée.
  3. enable puis show version (Espace pour dérouler). Mots de passe courants en salle : int, imt, tsp, cisco, class.
  4. Sortir par Ctrl-A k y.
Pourquoi relever le numéro de série plutôt que le nom ?

Le nom (hostname) a pu être changé par le binôme précédent ; le numéro de série, en bas de show version, identifie l'équipement de façon fiable.

TP · Une VM qui voit les deux mondes VirtualBox + routeur

Objectif : une VM qui joint à la fois Internet (carte NAT, enp0s3) et le routeur de la maquette en 10.0.1.254 (carte en pont sur net1, enp0s8).

  1. Importer la VM (Fichier → Importer, en générant de nouvelles adresses MAC), puis régler Adapter 1 en NAT et Adapter 2 en Bridged Adapter sur net1.
  2. Sur le routeur, par la console : 
    Router# configure terminal
Router(config)# interface GigabitEthernet0/0/1
Router(config-if)# ip address 10.0.1.254 255.255.255.0
Router(config-if)# no shutdown
  3. Dans la VM : sudo nmcli dev set enp0s8 managed no, sudo ip link set enp0s8 up, sudo ip address add 10.0.1.10/24 dev enp0s8.
  4. Vérifier : ping -c 1 8.8.8.8 et ping -c 1 10.0.1.254 répondent tous les deux.
Faut-il ajouter une route par défaut via 10.0.1.254 ?

Non. 10.0.1.254 est dans le réseau 10.0.1.0/24 directement connecté, donc joignable sans route. La route par défaut doit rester celle de la carte NAT, sinon on perd Internet.

TP · Capturer un ping Wireshark

Objectif : depuis la VM précédente, capturer un ping vers le routeur, et seulement le ping.

  1. Lancer la capture sur enp0s8 (la carte en pont).
  2. Dans la VM : ping -c 3 10.0.1.254, puis arrêter la capture.
  3. Filtrer à l'affichage : icmp. On voit les paires Echo (ping) request / Echo (ping) reply.
Pourquoi rien n'apparaît si l'on capture sur enp0s3 ?

C'est la carte NAT, qui mène à Internet : le ping vers 10.0.1.254 sort par la carte en pont et ne passe jamais par elle.

Le filtre icmp a-t-il supprimé l'ARP de la capture ?

Non, un filtre d'affichage masque sans rien jeter : effacer le filtre fait réapparaître l'ARP et le reste du trafic.

Testez-vous

1. Que faire de la configuration d'un switch en fin de TP ?

Rien : ne pas la sauvegarder. La running-config disparaît au redémarrage, l'équipement est rendu propre au binôme suivant.

2. Vous tapez sudo ip address add 10.0.1.10 dev enp0s8 et le ping vers 10.0.1.254 échoue. Pourquoi ?

Le masque manque : Linux pose un /32 et la machine ne considère aucune autre adresse comme voisine. Il faut 10.0.1.10/24.

3. screen /dev/ttyUSB0 9600 renvoie « Permission denied ». Que faire ?

Relancer avec sudo : le port série n'est accessible qu'à root et au groupe dialout.

4. Un camarade obtient « Resource temporarily unavailable » en ouvrant la console. Pourquoi ?

Une ancienne session screen (fenêtre fermée ou détachée) tient encore le port. sudo screen -ls puis sudo screen -X -S <id> quit. Pour l'éviter : sortir par Ctrl-A k y.

5. Votre VM en NAT ne parvient pas à pinguer le switch de la maquette. Quel mode faut-il ?

L'accès par pont sur net1 : la VM devient une machine du réseau de la maquette. En NAT, elle est cachée derrière un routeur privé de VirtualBox et ne sort que vers Internet.

6. Vous tapez host 10.0.1.10 dans la barre de filtre de Wireshark et elle devient rouge. Pourquoi ?

host est la syntaxe du filtre de capture. Dans la barre du haut (filtre d'affichage), il faut ip.addr == 10.0.1.10.
