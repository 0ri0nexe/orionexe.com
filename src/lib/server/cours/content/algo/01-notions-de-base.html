Chapitre 01

Introduction et notions de base

Un algorithme décrit, dans un langage simple, la suite d'actions qui transforme les données d'un problème en résultats. Ce chapitre pose les briques du langage algorithmique du cours : types, variables, affectation, et les trois structures de contrôle.

Organisation du module (CSC 8445)

Séances : 6 séances de 3 h (cours, TD, corrigé) : 1) notions de base, 2) fonctions et types composites, 3) tris itératifs et récursifs, 4) listes, piles et files, 5) arbres, 6) révision.

Évaluation : deux contrôles sur papier, CC et CF1, plus une note de participation NP. NF1 = (2×NP + 6×CC + 12×CF1) / 20. Si besoin, un CF2 : NF2 = (2×NP + 6×CC + 12×CF2) / 20. Note finale : NF = max(NF1, min(NF2, 13)).

Outils : papier et crayon, dans le langage algorithmique du cours (voir l'antisèche de syntaxe). Supports et TD sur le portail informatique.

L'essentiel en 30 secondes
  • Démarche : problème → spécification → algorithme → programme. On spécifie les données, les résultats et leurs relations, puis on décrit la méthode.
  • Types prédéfinis : entier, réel, caractère, chaîne, booléen. Toute variable est déclarée avec son type (entier n, m = 3).
  • Affectation : variable = expression ; comparaison d'égalité : ==. Entrées/sorties : saisir, afficher, allerALaLigne.
  • Sur les entiers : div (quotient) et mod (reste) ; sur les réels : /.
  • Trois structures de contrôle : séquence, choix (si … fsi, cas où … fcas), itération (tant que … ftq, faire … tant que, pour … fpour).

Du problème au programme

Un programme est caractérisé par un ensemble de données, un ensemble de résultats, et une solution : la description, dans un langage, d'actions à exécuter dans un certain ordre. Exemple de problème : déterminer l'élément minimum d'une suite d'entiers.

Trois principes méthodologiques :

  • Abstraire : retarder le plus possible le codage ; décrire d'abord les actions dans un langage simple.
  • Décomposer : diviser chaque difficulté en sous-problèmes (Descartes).
  • Combiner : résoudre le problème global en assemblant les solutions des sous-problèmes.

Un algorithme est la description précise du processus de résolution d'un problème bien spécifié : une séquence ordonnée d'actions sur les données qui produit le résultat. Il doit être lisible sans connaître le langage cible.

Pour comprendre : ce qu'on attend en TD

Chaque exercice commence par un énoncé du problème en trois rubriques : Données (ex. deux entiers nbPersonnes, nbGroupes), Résultats (ex. quatre entiers), Relations entre données et résultats (ex. l'effectif des petits groupes vaut nbPersonnes div nbGroupes). Ensuite seulement on écrit l'algorithme : saisie, calcul, affichage.

Types et variables

Un type définit l'ensemble des valeurs possibles d'une information et les opérations permises dessus. Tout type a un nom ; toute information a un type et un identifiant.

Une variable est une donnée modifiable : un contenant (abstraction d'un emplacement mémoire) dont la valeur peut changer. La définition est obligatoire, l'initialisation facultative :

Actions et opérateurs

Affectation, saisie, affichage

L'affectation variable = valeur range dans la variable la valeur d'une expression, évaluée à l'exécution avec l'état courant des variables. Dans x = x + 1, on lit l'ancien x, on ajoute 1, puis on écrase x.

saisir ( x )                     // x : variable de type simple
afficher ( "x + 1 = " , x + 1 )  // affiche plusieurs éléments à la suite
allerALaLigne ( )                // passe à la ligne suivante

La saisie modifie la variable : elle utilise implicitement l'affectation. Une action composée est un ensemble d'actions simples organisées par les structures de contrôle.

Les opérateurs

CatégorieOpérateurs
Logiques (booléens)non, et, ou
Arithmétiques (entier et réel)+, −, ×
Entiers seulementdiv (division entière), mod (reste)
Réels seulement/ (division réelle)
Comparaison== (égalité), ≠ (différent), et dans les exemples <, >, ≤, ≥

Exemples : 17 div 5 vaut 3, 17 mod 5 vaut 2. Un entier n est pair si n mod 2 == 0. n div 10 retire le dernier chiffre de n, n mod 10 donne ce chiffre.

Piège classique : = et ==

= est l'affectation (une action), == la comparaison (une expression booléenne). On écrit si x == 3 alors, jamais si x = 3 alors. De même, / est réservé aux réels : pour un quotient entier, c'est div.

Le schéma séquentiel

Les actions s'exécutent dans l'ordre où elles apparaissent. Un algorithme se compose de la déclaration des variables puis du corps.

entier a, b, c       // déclaration des variables
saisir(a)            // corps de l'algorithme
saisir(b)
c = a + b
afficher(c)

Exemple : échanger deux variables

entier n , m , aux
saisir ( n )
saisir ( m )   // #0 : n = 5, m = 7
aux = n        // #1 : sauvegarde de n
n = m          // #2 : m copié dans n
m = aux        // #3 : ancienne valeur de n copiée dans m
afficher ( n ) // affiche 7
afficher ( m ) // affiche 5

Piège classique : échanger sans variable auxiliaire

Écrire n = m puis m = n donne n = 7, m = 7 : la valeur 5 est écrasée dès la première affectation. Il faut la sauvegarder dans aux avant.

Le schéma alternatif (de choix)

Une ou des actions sont conditionnées par une expression booléenne, la condition. Mots réservés : si alors sinon fsi. La branche sinon est optionnelle.

entier x , y , max
saisir(x)
saisir(y)
si x > y alors           // solution 1 : si … sinon
    max = x
sinon
    max = y
fsi

max = x                  // solution 2 : forme simplifiée
si x < y alors
    max = y
fsi

Le choix généralisé : cas où

Évite une cascade de si imbriqués : compare une valeur v entière à une série de constantes entières. On exécute l'action de la première constante égale à v, puis on quitte le cas. autre (optionnel) s'exécute si aucune constante ne correspond.

entier jour
saisir(jour)
cas où jour vaut
    6 : afficher("samedi")
    7 : afficher("dimanche")
    autre : afficher("semaine")
fcas

Pour comprendre : quand choisir quelle boucle

Nombre de tours connu (parcourir 1 à n, les cases d'un tableau) : pour. Arrêt sur une condition, possiblement sans aucun tour : tant que. Action à faire au moins une fois (saisie à vérifier, menu) : faire … tant que. Dans un tant que, l'action doit modifier une variable de la condition, sinon la boucle ne s'arrête jamais.

La boucle pour

entier n
saisir(n)
entier somme = 0
pour entier i = 1 à n faire
    somme = somme + i
fpour
afficher( somme )

entier sommePairs = 0
pour entier i = 2 à n pas 2 faire   // i = 2, 4, 6, …
    sommePairs = sommePairs + i
fpour

Les bornes sont incluses : pour entier i = 1 à n fait n tours. Avec n = 4, somme passe par 1, 3, 6, 10.

Piège classique : boucles imbriquées

La boucle intérieure est entièrement rejouée à chaque tour de la boucle extérieure : 3 tours × 2 tours = 6 exécutions du corps. Si la borne intérieure dépend de i (pour entier j = 1 à i), le nombre de tours change à chaque ligne : 1, 2, 3…

4. Que fait tant que n ≠ 0 faire n = n div 10 ; c = c + 1 ftq avec c = 0 au départ ? (quiz 1)

Il compte le nombre de chiffres de n : chaque div 10 enlève un chiffre. (Attention : pour n = 0, la boucle ne tourne pas et c vaut 0.)

5. Qu'affiche ce double pour ? (quiz 1) 
pour entier i = 1 à 4 faire
    pour entier j = 1 à i faire
        afficher('x')
    fpour
    allerALaLigne()
fpour

Un triangle : x, xx, xxx, xxxx sur 4 lignes. La ligne i contient i caractères.

6. Que valent 23 div 4 et 23 mod 4 ? Comment tester qu'un entier a est divisible par b ?

5 et 3, car 23 = 4 × 5 + 3. Divisible si a mod b == 0.

7. Quelle différence entre tant que … ftq et faire … tant que ?

Le tant que teste avant : l'action peut ne jamais être exécutée. Le faire … tant que teste après : l'action est exécutée au moins une fois.

8. Après entier a = 2, b = 9 puis a = b et b = a, que valent a et b ?

a = 9 et b = 9 : l'ancienne valeur de a est perdue. Pour échanger, il faut une variable aux.

9. Dans cas où v vaut, quel type doit avoir v, et que se passe-t-il si aucune constante ne correspond ?

v est une valeur entière. Si aucune constante n'est égale à v, on exécute la branche autre si elle existe, sinon rien.
